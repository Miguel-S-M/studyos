======================================================================
1. VISÃO GERAL
======================================================================

Nome provisório: StudyOS
Assistente integrado: Holo

Objetivo:
Criar um ambiente completo para estudar, organizar tarefas, acompanhar o
tempo de foco, aprender de forma mais eficiente, guardar conhecimentos e
analisar a própria evolução. O site deve ser útil mesmo sem conta e sem
internet para as funções centrais, com sincronização em nuvem opcional.

Princípios do produto:
- Registrar o estudo sem tornar o sistema complicado.
- Medir não apenas horas estudadas, mas também compreensão e retenção.
- Funcionar primeiro no navegador, sem obrigar o usuário a criar uma conta.
- Permitir ativar sincronização em nuvem quando o usuário quiser.
- Manter os dados pessoais privados, mesmo com o código-fonte público.
- Ter uma interface rápida, acessível, responsiva e visualmente consistente.
- Começar com serviços gratuitos sempre que possível, respeitando os limites
  e termos de cada provedor.
- Desenvolver os módulos em etapas, com testes e segurança desde o início.

2. HOSPEDAGEM E ARQUITETURA
======================================================================

Decisões confirmadas:
- Repositório público no GitHub.
- Publicação do site pelo GitHub Pages.
- Orçamento inicial: priorizar serviços gratuitos.
- Armazenamento local por padrão, com sincronização opcional.
- O código-fonte do projeto ficará centralizado em um único repositório.
- O site deverá continuar funcionando para as funções centrais sem conta.

Tecnologias propostas:
- React: interface e componentes.
- TypeScript: tipos e maior segurança no desenvolvimento.
- Vite: desenvolvimento e compilação.
- Tailwind CSS: sistema de estilos.
- React Router: navegação entre páginas.
- IndexedDB com Dexie: banco de dados local no navegador.
- Zod: validação de dados.
- Recharts: gráficos e estatísticas.
- Vitest e Testing Library: testes automatizados.
- GitHub Actions: compilação e publicação automática no GitHub Pages.
- Supabase opcional: autenticação, banco de dados e sincronização em nuvem.
- Supabase Edge Functions ou backend equivalente: chamadas seguras à IA e
  serviços que necessitem de segredo no servidor.

Limitação essencial:
GitHub Pages hospeda arquivos estáticos. Não executa um servidor privado.
A interface, timers e funções locais podem funcionar ali. Recursos que
precisem de chaves secretas, como chamadas a certos provedores de IA, devem
usar uma função de servidor hospedada separadamente. O código dessa função
pode ficar no mesmo repositório, mas a execução será feita pelo serviço
externo.

Modo local:
- Guardar dados no navegador usando IndexedDB.
- Permitir exportar os dados para arquivo JSON e importá-los depois.
- Avisar que limpar os dados do navegador ou perder o dispositivo pode
  eliminar dados que não tenham sido exportados.
- Não tratar o armazenamento local como backup permanente.
- O modo local não sincroniza automaticamente entre computadores.

Modo sincronizado opcional:
- Permitir que o usuário crie uma conta e conecte seus dados à nuvem.
- Usar políticas de segurança no banco para que cada pessoa acesse somente
  seus próprios registros.
- Ter fluxo de migração que apresente os dados locais, detecte possíveis
  duplicatas e peça confirmação antes de mesclar.
- Tratar conflitos de edição sem apagar informações silenciosamente.
- Oferecer exportação e exclusão dos dados pessoais.
- Não exigir sincronização para usar as funções básicas do site.

5. FOCO E CRONÔMETROS
======================================================================

Modos:
- Cronômetro livre.
- Pomodoro configurável.
- Contagem regressiva.
- Sessão com objetivo de duração.
- Temporizador de pausa.

Controles:
- Iniciar, pausar, retomar, finalizar e cancelar.
- Escolher matéria e, opcionalmente, tarefa.
- Adicionar notas à sessão.
- Associar música, playlist ou vídeo, quando disponível.
- Configurar duração de foco, pausas curtas e pausas longas.
- Permitir que o usuário escolha se deseja notificações.
- Recuperar uma sessão ativa depois de recarregar a página.
- Manter a sessão ao navegar entre páginas.
- Não criar duas sessões para o mesmo período por erro de clique ou múltiplas abas.

Precisão:
- Calcular tempo usando timestamps reais de início, pausa, retomada e fim.
- Não depender exclusivamente de um contador que aumenta a cada segundo.
- Guardar pausas separadamente.
- Não contar pausas como tempo de foco.
- Tratar sessão que atravessa meia-noite, mudança de fuso e relógio do sistema.
- Detectar sessão abandonada e oferecer uma decisão ao usuário.
- Evitar duplicação quando houver várias abas abertas.

Registro de sessão de estudo:
- Identificador.
- Matéria.
- Tarefa opcional.
- Tipo de cronômetro.
- Data/hora de início e fim.
- Duração focada.
- Pausas e durações.
- Estado.
- Notas.
- Mídia associada opcional.
- Origem do registro: local ou sincronizada.

======================================================================

Holo é o assistente integrado ao StudyOS. A interface pode existir sem IA
ativa, mas respostas geradas exigirão um provedor configurado.

Personalidades:
- Martin: firme, direto e disciplinado, sem humilhar.
  Exemplo: "Você não precisa estar motivado. Precisa dar o primeiro passo."
- Lumi: acolhedora e paciente.
  Exemplo: "Você não precisa resolver tudo hoje. Vamos resolver a próxima coisa."
- Sage: analítica e estratégica.
  Exemplo: "Qual atividade mais aproxima você da sua meta hoje?"
- Pixel: descontraída e lúdica.
  Exemplo: "Missão aceita. Vamos vencer esses exercícios?"
- Atlas: professor que estimula recordação ativa.
  Exemplo: "Tente explicar o conceito com suas próprias palavras antes de consultar a resposta."

Funções:
- Conversar sobre estudo.
- Ajudar a planejar o dia ou a semana.
- Recomendar uma próxima tarefa com base nos dados autorizados.
- Explicar conceitos em diferentes níveis.
- Criar perguntas, exercícios e flashcards.
- Resumir insights selecionados.
- Fazer revisão semanal.
- Identificar matérias pouco estudadas quando houver dados suficientes.
- Sugerir uma sessão ou Pomodoro, pedindo confirmação antes de iniciar ações.
- Permitir ajustar tom, intensidade e frequência das mensagens.
- Permitir desativar mensagens motivacionais e notificações.
- Permitir optar por salvar ou não o histórico de conversas.

Contexto e privacidade:
- Enviar ao serviço de IA somente os dados necessários à solicitação.
- Nunca expor a chave de IA no frontend.
- Usar função de servidor, autenticação e limites de uso.
- Não enviar notas privadas automaticamente sem necessidade e consentimento.
- Distinguir dados reais de inferências e sugestões.
- Não inventar estatísticas pessoais.
- Não usar mensagens humilhantes, coercitivas ou agressivas.
- Exigir confirmação para ações com efeitos relevantes.

18. SEGURANÇA PARA O REPOSITÓRIO PÚBLICO
======================================================================

Permitido no repositório:
- Código da interface e componentes.
- Configuração pública do frontend.
- Esquemas e migrações do banco sem credenciais.
- Regras de segurança e documentação.
- Arquivo .env.example com nomes de variáveis e valores fictícios.
- Testes e workflow de publicação.

Nunca enviar ao repositório:
- Chaves secretas de IA.
- Tokens pessoais ou de acesso.
- Senhas de banco.
- Chaves administrativas/service-role.
- Segredos OAuth.
- Arquivos .env reais.
- Backups com dados de usuários.
- Dados pessoais reais usados em testes.

Medidas:
- Manter .gitignore desde o primeiro commit.
- Ativar e conferir a proteção contra envio de segredos do GitHub, quando disponível.
- Usar variáveis/segredos no serviço de servidor para credenciais privadas.
- Tratar qualquer chave pública como visível para todos.
- Não confiar apenas em esconder botões ou rotas no frontend.
- Aplicar autenticação e políticas RLS no banco sincronizado.
- Limitar uso de endpoints de IA e serviços externos.
- Validar entradas e tratar erros.
- Atualizar dependências e revisar alertas.
- Se um segredo for exposto, revogá-lo/rotacioná-lo; apagar o arquivo não basta.
- Não colocar dados pessoais nos logs.
- Testar autorização com duas contas diferentes.
- Documentar retenção, exportação e exclusão de dados.

======================================================================
23. DEFINIÇÃO DE PRONTO
======================================================================

Uma funcionalidade só será considerada concluída quando:
- Funcionar no uso real, não apenas visualmente.
- Salvar e recuperar dados corretamente.
- Ter estados de carregamento, vazio e erro.
- Ser utilizável em computador e celular.
- Ter validações e tratamento de falhas.
- Não expor segredos nem dados privados.
- Ter testes apropriados.
- Ser documentada no README quando necessário.

Não simular integrações como se fossem reais. Se uma API ainda não estiver
configurada, mostrar claramente que o recurso está indisponível ou oferecer
uma alternativa funcional.

======================================================================
24. RESUMO DAS DECISÕES
======================================================================

- Nome provisório: StudyOS.
- Assistente: Holo, com personalidades selecionáveis.
- Visual: premium escuro, preto/grafite com cobre e laranja.
- Hospedagem da interface: GitHub Pages.
- Código-fonte: um único repositório público no GitHub.
- Dados: local por padrão, sincronização opcional.
- Orçamento: começar com serviços gratuitos.
- Tecnologia: React, TypeScript, Vite e Tailwind CSS.
- Armazenamento local: IndexedDB.
- Nuvem opcional: Supabase, com políticas de segurança.
- Holo/IA: função de servidor; chave secreta nunca no frontend.
- Spotify e YouTube: implementar conforme permissões e limites atuais.
- Desenvolvimento: por etapas, começando pela fundação e pelo núcleo de estudo.
- Segurança: privacidade por padrão, exportação de dados e nenhuma credencial
  privada no repositório público.
